Reorganizing Learn around the user's job, not our content types

Low-fi wireframes only — boxes and labels, zero visual design. The point is structure: what goes where and why. Yellow notes explain the reasoning on every screen.

The organizing principle
1 · Learn the System
Depth, in order. For the newcomer ("what is this?") and the student working through it seriously.
Start Here The Playbook Book Academy
2 · Get an Answer
A problem, today, any format. The biggest segment — the They Ask, You Answer audience by definition.
Search Topics Tools & Templates
3 · Stay Current
"What's new since last time?" Returning subscribers and fans.
Latest Webinars Podcast Subscribe
! Every page, label, and nav item belongs to exactly one job. The old structure (Knowledge Base / Insights / Podcast / Webinars / Tools) mapped to our CMS, not to anyone's intent.
What changed from the current structure
  • Knowledge Base → "The Playbook." Same content, honest name: the system, in order, free. Sets up "read the book or work the Playbook online."
  • Recent Insights → "Latest." Becomes one feed: new articles + new podcast episodes + announced webinars. Fixes the KB-vs-Insights confusion (a first-time visitor can't tell two kinds of "articles" apart).
  • "What Is Endless Customers" stops being a menu item. It becomes the front of the Start Here journey.
  • Book & Academy demoted from siblings to destinations. They're where the depth track leads, not competing menu entries.
  • Topics + Search promoted to primary navigation. ~100 topics, two levels (≈12 parents), type-ahead or drill-down, cross-content topic pages. HubDB multilevel dynamic pages handle this natively.
  • Learn subnav has no CTA. Main nav keeps Diagnostic + Let's Talk at full strength (services pages keep their conversion-style subnav — different job).
